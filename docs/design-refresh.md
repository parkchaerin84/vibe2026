## 화면 방향

- 핑크 `#F7A8C4`, 하늘색 `#A8D8F0`, 배경 `#FFF9FC`, 강조 버튼 `#E86A9A`, 본문 `#333740`.
- 홈의 주요 행동은 하차 정보 공유. 편의시설·커뮤니티를 바로 찾을 수 있는 세 개의 기능 카드와 보조 즐겨찾기를 배치.
- 2호선은 공식 초록색 `#00A84D` 점과 별도 노선 배지로 구분. 기존 노선 색상 설정과 저장된 즐겨찾기는 변경하지 않음.
- 시설 화면의 화장실은 실제 조회 기능, 엘리베이터·에스컬레이터는 데이터 연동 준비 중으로 표시. 새 시설 데이터나 조회 API를 만들지 않음.
- 기존 안내 중 빈 좌석 보장 불가, 개별 열차 구분 불가, 30분 만료, 공식 민원 아님, 브라우저 삭제 시 작성 권한 상실 가능성은 유지. 부가 설명은 기본 HTML details/summary로 정리.
- 로고는 기존 파일 사용. 홈의 열차 그림은 장식용 SVG이며 실제 열차 위치·운행 경로·실시간 데이터가 아님.

## 검증

- `npm run typecheck`, `npm test` 전체 63개 통과, `npm run build` 및 빌드 내부 lint/타입 검사 통과.
- `lib/`, `server/`, `functions/`, `data/`의 기존 18개 파일은 작업 전후 해시 동일. Supabase·인증·소유권·API 키 보호·역 코드·캐시·30분 만료·즐겨찾기 저장 로직을 변경하지 않음.
- 최종 공개 출력 55개 파일에서 시설 API 키의 원문·디코딩·URL 인코딩 변형 미검출. main 커밋은 기존 `3cc1a8fc59d038363248d74c605fcb80de5eaed6` 그대로.
- 브라우저에서 320/375/768px × 홈·하차 공유·시설·커뮤니티·긴급 안내 총 15개 조합 확인: 문서 가로 넘침 없음, 페이지별 h1 하나와 현재 메뉴 하나.
- 데스크톱 홈·즐겨찾기 펼침, 하차 공유 입력 폼, 커뮤니티 작성 폼, 시설 위치정보와 긴급 안내 확인.
- Tab으로 본문 바로 가기 링크에 접근하고 Enter로 본문 초점 이동 확인. 작성 폼을 열면 하차 공유의 현재 역과 커뮤니티의 제목에 초점 이동.
- 320px 작성 폼에서도 가로 넘침 없음. 실제 입력창 높이 48px·글자 16px, 긴 글 입력칸 기본 높이 140px 확인. 빈 게시글의 제출 버튼은 비활성 상태 유지.
- 하차 공유의 강남·내선순환 선택 시 다음 역 교대 표시 유지. 실제 등록·수정·삭제는 실행하지 않음.
- 잠실 화장실 실제 조회 1회: 위치 원문 `대합실 1층 1,2번 출입구 앞`, B1, 데이터 기준일 2021-05-27과 별도 근접 출입구 필드 유지. 시설 종류를 바꾸는 가상 조회 없음.
- 커뮤니티의 실제 공개 조회 결과는 빈 목록이었음. 실제 글·댓글을 새로 만들지 않았으며 CRUD 동작은 기존 격리 회귀 테스트로 확인.
- 본문/배경 11.47:1, 강조 버튼 글씨/배경 5.63:1, 보조 글씨/흰 배경 6.64:1, 노선 배지 글씨/배경 6.85:1. 입력창 테두리/흰 배경 3.15:1, 초점 표시/기본 배경 7.91:1. 핵심 조합을 확인한 결과이며 전체 WCAG 적합성 인증을 의미하지 않음.
- .next 캐시의 EPERM 쓰기 문제는 해당 캐시 경로 쓰기 권한을 받아 해결. 캐시·프로젝트 파일 삭제 없음.
- DB 변경·SQL·인증 설정 변경·커밋·푸시·운영 배포 없음. 기존 신분당선 데이터와 기능 보존.

## 확인 주소

`http://127.0.0.1:3002/`

같은 미리보기 서버에서 `/share-seat`, `/facilities`, `/community`, `/emergency`를 확인한다. 시설 조회는 Pages Function과 같은 핸들러를 실행하는 로컬 서버를 사용한다. Cloudflare 네이티브 실행이나 원격 배포는 이번 검증 범위가 아니다.

현재 서버를 종료한 뒤 다시 열 때는 프로젝트 폴더에서 `npm run preview:facilities`를 실행한다. 사이트를 직접 사용해 등록 버튼을 누르면 실제 DB에 저장되므로, 디자인 검토 중에는 새 글을 제출하지 않아도 된다.
