# 하차 공유: 신분당선·2호선

## 데이터와 경로의 역할

- 화면의 역 이름·UUID·노선 소속은 Supabase 공개 조회 결과를 사용한다. 조회 실패·누락·이름/코드/구간 불일치 시 등록을 막고 오류를 표시한다. 예시 역이나 제보로 보완하지 않는다.
- `lib/transit/share-stations.json`은 2026-11-08 검토한 공식 자료의 코드·이름·구간 스냅샷이다. 2호선은 승인한 추가 SQL의 51행, 신분당선은 승인한 16행을 기준으로 한다. JSON의 자료 출처와 SQL 원본 해시를 함께 보관한다.
- `lib/transit/share-routes.ts`는 별도 검증한 연결 순서를 정의한다. DB의 정렬 결과나 코드 숫자순으로 경로를 추측하지 않는다. 용두 `0250`, 까치산 `0200`도 정확한 지선 위치에 둔다.
- 신분당선 16역, 2호선 본선 43역, 성수지선 5역, 신정지선 5역이다. 지선의 5역에는 각각 본선 연결역 성수·신도림이 포함되므로 DB의 고유 역 개수는 51개다. 연결역의 station/membership UUID는 중복 생성하지 않는다.
- 신분당선 경로 순서는 [운영사 노선도](https://www.shinbundang.co.kr/dxline/dxline_gy.jsp), 2호선은 [서울교통공사 노선도](https://www.seoulmetro.co.kr/kr/cyberStation.do)와 [공식 역 정보](https://data.seoul.go.kr/dataList/OA-15442/S/1/datasetView.do)를 기준으로 검토했다.

## 방향과 범위

- 본선 내선은 시청→을지로입구→…→충정로→시청, 외선은 반대다. 강남의 내선 다음 역은 교대, 외선은 역삼이다. [서울시 방향 설명](https://mediahub.seoul.go.kr/archives/1076164)을 기준으로 한다.
- 순환선에서는 현재 역을 제외한 42개 본선 역이 양쪽 방향 모두에서 한 바퀴 이내 도달 가능하다. 최단 방향을 강제하지 않는다.
- 성수지선은 성수↔용답↔신답↔용두↔신설동, 신정지선은 신도림↔도림천↔양천구청↔신정네거리↔까치산이다. 지선 방향은 양끝 역 이름을 사용하고 내선·외선을 적용하지 않는다.
- 한 제보는 한 구간만 대상으로 한다. 본선↔지선 또는 지선↔지선 환승이 필요한 제보는 막는다. 연결역까지 또는 연결역부터의 같은 구간 제보는 허용한다.
- 경로 검사는 선로 연결에 따른 검사다. 실제 탑승 열차의 종착역, 운행 변경, 도착 시각, 빈 좌석을 보장하지 않는다. 서로 다른 제보를 칸 번호로 합산하지 않는다.

## 보안과 기존 기능

- 읽기는 공개 클라이언트, 작성 시 기존 Anonymous Auth, 본인 확인은 기존 `my_content_ids` RPC와 RLS를 유지한다. `owner_id`를 직접 조회하지 않는다.
- 작성 payload는 허용한 5개 컬럼만 전송하고 UUID·작성자·만료 시각을 임의 전송하지 않는다. 등록·삭제 자동 재시도는 하지 않는다. DB의 30분 만료 및 쓰기 제한을 유지한다.
- 이번 방향·도달 가능성 검사는 클라이언트 검증이다. 기존 DB 외래키는 같은 노선 소속을 검증하지만 방향/구간/순서를 서버에서 검증하지는 않는다. 직접 REST 요청으로 클라이언트 검증을 우회하는 문제까지 해결했다고 주장하지 않는다. 서버 경로 검증은 별도 승인할 향후 과제다.
- DB 구조/SQL/정책/데이터, 커뮤니티·즐겨찾기·기존 신분당선 조회 코드는 변경하지 않는다. Cloudflare Pages용 `output: export`를 유지하며 런타임 서버를 추가하지 않는다.

## 브라우저 확인 방법

1. `/share-seat`에서 기본 신분당선의 16역과 기존 제보를 확인한다. 강남→판교는 광교 방면으로 선택한다. 신사 방면에서는 판교 선택이 비활성화되어야 한다.
2. 노선을 2호선, 구간을 본선으로 변경한다. 현재 역에는 43역만 나오고 용답·까치산은 나오지 않아야 한다.
3. 강남에서 내선을 선택하면 다음 역 교대, 외선을 선택하면 역삼으로 표시되는지 확인한다. 충정로 내선은 시청, 시청 외선은 충정로다.
4. 성수지선에는 성수·용답·신답·용두·신설동 5역, 신정지선에는 신도림·도림천·양천구청·신정네거리·까치산 5역이 이 순서로 표시되는지 확인한다.
5. 용답에서 성수 방면이면 신답/용두/신설동이 비활성화되고 성수만 선택할 수 있어야 한다. 방향/현재 역/구간/노선을 바꾸면 이전 하차 역 선택이 초기화되어야 한다.
6. 실제 제보 테스트는 사용자가 직접 한다. A 브라우저에서 구간·방향을 골라 등록하고 B 시크릿 창에서 같은 노선·구간을 선택해 조회한다. B에는 A의 삭제 버튼이 없어야 한다. A에서 삭제하고 B에서 새로고침한다.
7. 30분 후 만료된 제보가 사라지는지 확인한다. 한 번에 한 건 제한은 노선을 바꾸어도 유지된다. 실제 테스트용 제보를 서비스 데이터와 혼동하지 않도록 테스트 직후 본인이 삭제한다.

## 검증 범위

자동 테스트의 가짜 UUID와 응답은 테스트 프로세스 안에서만 사용한다. 실제 DB에는 테스트 제보를 쓰지 않는다. 타입 검사·전체 테스트·lint·정적 빌드와 공개 DB 조회를 확인한다. 실사용자 간 새 2호선 등록·삭제는 위 절차로 별도 확인한다.
