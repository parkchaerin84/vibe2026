# 서울 2호선 화면 범위

- `lib/transit/service-scope.ts`의 표시 범위는 `line2`다. 두 노선의 공식 자료, 신분당선 전용 조회 코드와 범용 등록/수정/삭제 로직은 삭제하지 않는다.
- 하차 공유는 2호선 공개 데이터만 조회하며 본선·성수지선·신정지선 검증은 유지한다.
- 커뮤니티는 2호선 참조 정보가 준비되기 전에는 게시글을 무조건 전체 조회하지 않는다. 목록은 항상 해당 2호선 UUID로 필터링하며, 다른 노선 글을 상세 조회한 경우 화면과 댓글에 표시하지 않는다. 기존 글/댓글/작성자 데이터는 DB에 남는다.
- 글쓰기 참조 목록도 2호선만 제공한다. 기존 신분당선 데이터를 2호선으로 변환하거나 새 노선 UUID를 만들지 않는다.
- 즐겨찾기의 원래 키 `subwayeasy_favorites`를 유지한다. 기존 원소와 추가 필드, 알 수 없는 항목을 보존하며, 현재 2호선 DB 목록에 일치하는 즐겨찾기만 적용/삭제할 수 있다. 다른 노선과 미확인 항목은 보관 개수만 안내한다.
- 데이터가 깨졌거나 배열이 아닌 저장 내용은 빈 배열로 덮어쓰지 않는다. 이 경우 저장/삭제를 막고 안내한다. 읽기/화면 진입만으로 LocalStorage를 쓰거나 마이그레이션하지 않는다.
- 추가/삭제 직전 최신 LocalStorage 내용을 다시 읽어 병합한다. 같은 ID를 가진 다른 노선의 항목도 2호선 삭제 작업으로 지워지지 않는다.
- 원래 홈 전체 구현은 `components/legacy/LegacyHome.tsx`에 보관한다. 이 컴포넌트는 사용자 라우트에서 렌더링하거나 링크하지 않는다. 향후 복구 시 표시 범위뿐 아니라 조회 필터·기존 저장 데이터 정책도 함께 검토해야 한다.
- DB 구조, SQL, 실제 사용자 데이터 변경이나 커밋/푸시/운영 배포는 이 작업에 포함하지 않는다.

## 브라우저 확인

1. 홈의 즐겨찾기에서 노선이 2호선 하나인지, 출발역 목록이 51개인지 확인한다.
2. 예전 다른 노선 즐겨찾기가 있다면 보관 안내가 나오고 2호선 선택에 자동 적용되지 않는지 확인한다. 저장소 원문을 지우지 않는다.
3. 2호선 즐겨찾기를 추가·삭제한 뒤 다른 노선 보관 항목이 유지되는지 확인한다.
4. 하차 공유에서 기본 노선이 2호선이고, 본선·두 지선이 유지되는지 확인한다.
5. 커뮤니티의 2호선 전체/역별 검색과 글쓰기 모두 2호선만 선택되는지 확인한다. 신분당선 게시글이 2호선 글로 바뀌어 표시되면 안 된다.

자동 테스트는 메모리의 격리된 입력/응답만 사용한다. 실제 DB나 사용자 LocalStorage에 테스트 항목을 생성하지 않는다.
